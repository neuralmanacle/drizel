# 10 October 2026: WAV foundation and promptable modulation vision

The first offline milestone is working: Drizel can load supported WAV audio into
its own buffer, write a float32 WAV, reload it, and compare the decoded samples.
The maintainer reported passing automated checks on macOS and a successful
round trip with a real stereo sample.

## Work completed

- Added a standard C++17 `SampleBuffer` with planar float storage and explicit
  channel count, frame count, and source sample rate.
- Added offline WAV loading for mono/stereo PCM16, PCM24, and float32, plus
  float32 writing that preserves the decoded sample values.
- Added checks for invalid or unsupported files, truncated audio, non-finite
  samples, excessive decoded memory, and existing output files.
- Added the command-line WAV round-trip experiment and CMake/CTest targets.
- Added 21 named audio-data test cases and a separate CLI usage check.
- Added a GitHub Actions workflow for Linux and macOS. Remote CI execution has
  not been recorded in this development log.
- Documented ownership, error handling, sample-rate policy, build steps, and
  code reading order, with detailed comments beside the implementation.
- Registered source, experiment, test, and documentation groups in Projucer.
  Offline tools remain separate CMake targets.

## Target-machine validation

The maintainer reported that the CMake build and automated tests passed on the
Mac after setting `DRIZEL_JUCE_PATH` to the local JUCE source folder. Compiler
detection reported AppleClang 21.0.0.21000334. The real-file experiment produced:

```text
Channels: 2
Sample rate: 48000 Hz
Frames: 2273072
Duration: 47.356 seconds
Verified: decoded samples match exactly.
Saved: ./build/roundtrip-check.wav
```

This verifies equality of the decoded audio and its channel count, frame count,
and sample rate after loading, writing, and reloading this file. The output is
float32 WAV; its container bytes and metadata are not expected to match the
source. The input encoding was not included in the reported output.

The starter plugin was also built and run, displaying its original
"Hello World!" editor. Sample loading is currently exercised through the offline
tool; its eventual file chooser, background loading, and audio-thread handoff
are not implemented.

Listening comparisons and long-file memory/runtime stress checks remain open.
The completed milestone covers offline audio data and file I/O; it does not
claim granular synthesis, live playback, host validation, or a finished UI.

## Audio concept clarified

A sample is one amplitude value for one channel. A frame contains a sample from
every channel at the same instant; bit depth describes each sample's encoding.
This stereo file therefore has 2,273,072 frames, containing 2,273,072 samples
in each channel and 4,546,144 individual sample values in total. Its duration
is `2,273,072 / 48,000`, or approximately 47.356 seconds.

## Project direction added

Drizel will explore **promptable modulation policies**: a musician describes
movement and a model proposes an editable rule that local modulation code can
execute. Grain scanning is the first proposed target:

- "very chaotic": irregular, bounded movement through a sample region.
- "go around in circles": a repeating scan with a wrap boundary.
- "one step forward two step back": a repeating directional step sequence.

These are proposed interpretations for experiments. The accepted policy would
run locally, with inference outside the audio thread and conventional controls
always available. No model or provider has been chosen, and no model integration
is included in this milestone. The idea is now reflected in the project README,
architecture, roadmap, and [design proposal](../promptable-modulation.md).
